How should Jev browse a dense Agoda page?

Ten ways to turn a 63–74k-character accessibility tree into a safe, typed browser decision. The recommendation is deliberately conservative: compress what Jev sees, keep execution deterministic, and make uncertainty useful.

Recommendation

Typed evidence compiler

Deterministically extract bounded evidence and unique allowed action candidates, then use Jev for narrow Choice/Noul judgments. Raw AX remains authoritative.

1 · Typed evidence compiler

recommend

One deep module accepts raw AX, goal, and allowed controls. It returns a bounded state object plus a private mapping from model-facing action IDs to fresh raw targets.

TypeSafe shape: Choice for next; Noul for target/readiness; optional Choice for page phase.

2 · Deterministic evidence lanes

Keep the current projection idea: compact origin header, exact permitted actions, and direct evidence matching the goal. It is the smallest fix and already clears the 24k failure.

Limit: keyword lanes can miss paraphrases and dynamic labels; add a semantic selector only where needed.

3 · Line retrieval + Jev reranking

Use code to tag and shortlist AX lines, then ask Jev to choose the best evidence line or say NONE. Keep the source line ID local and copy only selected text into the next state.

Best for: facts hidden behind varied wording. Chunk or beam-search when more than 255 candidates exist.

4 · Semantic state delta

After the first decision, send a self-contained delta: current action context, relevant additions, changes, and removals. Fall back to the full projection whenever the delta is ambiguous or larger.

Limit: it reduces repeated input; it does not solve first-observation compaction.

5 · Typed AX intermediate representation

Compile lines into records such as {id, role, name, evidence, safeAction}. This creates a stable seam between CUA quirks and Jev questions, and makes tests express domain behavior rather than string parsing.

Trade-off: more initial parser work, but the highest long-term locality.

6 · Viewport / region pagination

Ask the browser runtime for a focused region or scroll window, then process one bounded region at a time.

Trade-off: elegant when the CUA API exposes reliable region semantics; fragile if the runtime only gives whole-page AX.

7 · Structural profile cache

Persist only allowlisted, page-family structure such as “rooms,” “policies,” and “children.” Use it to choose evidence lanes without storing URLs, snapshots, prices, or private text.

Trade-off: useful optimization, but a cache must never be required for correctness.

8 · Confidence-gated action router

Make Jev choose among ACT, WAIT, VERIFY, and BLOCKED. Code applies action-specific confidence thresholds and never treats confidence as proof.

Role: this is a guard around every other design, not a replacement for compaction.

9 · Speculative fan-out

Ask several independent questions over the same bounded state: next action, page phase, target presence, and whether the goal evidence is sufficient. Code ignores irrelevant branches.

Benefit: avoids serial Jev calls when the questions share one observation.

10 · Reasoning-model fallback

When deterministic extraction cannot produce a bounded state, route to a slower reasoning model or Codex with an explicit handoff rather than repeatedly retrying Jev.

Trade-off: robust escape hatch, but it treats the root cause with a more expensive path.

Best design

A small interface, a deep implementation

Expose one module seam: prepareDecision(rawAX, goal, allowedControls). Internally it parses, filters, ranks, labels, and bounds evidence. The caller receives a model-safe state plus an opaque action map. Jev never needs to know accessibility indices.

Leverage

One fix serves Agoda and future dense sites.

Locality

Compaction and safety live behind one seam.

Testability

Pure projection tests plus raw-action integration tests.

Typed judgments

Ask Jev only what code cannot decide

Choice · next

execute candidate

“Which allowed action is the best next mechanical step, or should we wait, finish, or hand off?”

Noul · ready

presence check

“Does the bounded evidence contain a visible room availability or price result?”

Code · policy

never model-decided

Origin allowlists, sensitive controls, fresh-state checks, index mapping, and final verification stay deterministic.

Confidence routes behavior; it does not certify that the page fact is true.

Why this wins

It solves the actual failure without making Jev the browser driver

1. It makes the first observation fit

The original failure happened before the first model call. Deterministic bounding removes the hard failure at the source.

2. It preserves a clean safety story

The model chooses an opaque action ID; code re-resolves it against fresh raw AX before execution.

3. It uses TypeSafe for semantics

Jev handles “which candidate fits?” and “is the target present?”—judgments that keyword rules cannot reliably own.

4. It degrades honestly

Projection failure, low confidence, stale state, or missing evidence produces a handoff or fallback, never a guessed click.
